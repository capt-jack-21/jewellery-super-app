## Limits handled in the UI (0.8.4)

- **Lot lines:** only lines with no tagged pieces get a remove button (`canRemoveLotLine`); tagged ones show "Has tagged pieces"
  and Save is blocked if one is missing. If the server still refuses, 409 `line_tagged` shows `error.line_tagged`. Lowering below
  tagged (422 `below_tagged`) and changing a tagged line's item (422 `errors[].code line_tagged`) stay blocked client-side.
  A `tagged` lot counts as open (`lotIsOpen`): editable, closable, "tag from" hidden only when nothing is left.
- **Draft transfers:** pieces taken off are listed by tag number in a confirm box before the PATCH; loose lines are kept as-is.
- **Stock-check report:** page `{items, next_cursor, counts}` — tabs not scanned / not expected / found with server counts,
  rows with item / purity / counter / tray (row `labels` first), current status, net weight, and the reason for extras;
  "Show more" follows `next_cursor`. Shown while running and after close.
- **Photos:** a second attach is 409 `already_attached` → plain "This photo is already on this piece."

## Live fix (5 Nov 2026, 2:52 PM IST) — stock check start crash

- Root cause (confirmed by Ironhide): `POST /v1/inventory/stock-checks` 201 returns the row **without `counts`** (required in
  `StockCheck`); `GET /stock-checks/{id}` has them. The running screen read `check.counts.matched` → TypeError → route error.
- UI now: `startAndLoadCheck` GETs the new check after the 201 and falls back to zero counts; every `counts` read goes through
  `checkCounts`, page `items` through `pageItems`, dates through `safeDateTime`; a 201 without `id` shows "could not be started".
  A place with no expected pieces shows a plain empty-state line.
- Closed by **contract 0.8.6** (backend `a9c8311`, 3:03 PM IST, sha256 `efff8489…84204da34440b5`): POST start, GET one, list
  items, close and cancel always carry the five counts (zeros on an empty scope, never null). The client guards stay
  (read-back GET after start, `checkCounts`, `pageItems`, `safeDateTime`) as defence. Scan list / report outcomes unchanged;
  `duplicate: true` only on a POST re-scan.
